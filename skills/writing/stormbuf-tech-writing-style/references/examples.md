# 正例与反例

> 11 组对照，覆盖 `google`、`ste`、`hybrid` 三种模式；含中英混排、操作步骤、错误信息、风险说明、中文句法专项与术语一致。
> 读法：先看反例的问题，再看正例改了什么；不要只背句子，按模式判断同类场景。

## 1. [google] 中英混排：第二人称与实义动词

**反例**：本 API 允许您对用户偏好数据进行获取操作。
**正例**：这个 API 让你读取用户偏好数据。接口返回 JSON，单个响应不超过 1 MB。
**改动**：反例用「您」与名词化「进行获取操作」；正例用第二人称和实义动词 `读取`。

## 2. [google] 条件前置与去主观词

**反例**：你可以简单地点击 **Delete** 按钮，如果你想删除整个文档的话。
**正例**：要删除整个文档，点击 **Delete**。
**改动**：正例把目的放在动作前，删掉 `简单地`，并把 UI 名加粗。

## 3. [google] 段落：关键信息前置

**反例**：在不同区域部署时需要考虑合规、延迟、成本等多种因素。另外还要考虑数据驻留要求。欧盟区域目前不可用。
**正例**：欧盟区域不可用。在其他区域部署前，评估合规、延迟、成本和数据驻留要求。
**改动**：反例把结论藏在段尾；正例第一句给结论，第二句给行动信息。

## 4. [ste] 操作步骤：一步一动作

**反例**：1. 在终端里执行下面的命令来安装依赖，然后修改配置文件，最后重启服务。
**正例**：

1. 在终端运行 `pnpm install`。
2. 在 `config.yaml` 中，把 `region` 设为 `ap-shanghai`。
3. 运行 `pnpm restart`。

**改动**：反例把三个动作塞进一步；正例每步一个动作，以祈使动词开头，命令用反引号。

## 5. [ste] 错误信息：对象、原因、下一步

**反例**：操作失败，请稍后重试。
**正例**：部署失败：`config.yaml` 第 12 行缺少必填字段 `region`。请补充 `region`，然后重新运行 `pnpm deploy`。
**改动**：反例没有对象、原因和可执行动作；正例写清失败对象、具体位置与下一步。

## 6. [ste] 风险说明：等级、指令、后果

**反例**：注意：操作不当可能导致数据损坏。
**正例**：**警告（Warning）**：不要在服务运行时删除 `data/` 目录。删除该目录会丢失未备份的数据，且无法恢复。
**改动**：反例风险等级弱、没有具体动作和后果；正例用等级词开头，先给禁止动作，再说明不可逆后果。

## 7. [hybrid] 代码变更汇报：五段协议

**反例**：我改好了，应该没问题。改了登录逻辑，你试试。
**正例**：

**状态**：完成。
**变更**：`src/auth/login.ts` 把重试次数从 3 改为 5；`src/config.ts` 新增 `RETRY_DELAY_MS`，默认值 `200`。
**证据**：`pnpm test auth` 通过（12 个用例）；端到端测试未运行。
**风险与假设**：假设生产环境未覆盖 `RETRY_DELAY_MS`；回滚方式是恢复这两个文件。
**待决策**：是否把重试延迟也做成环境变量？

**改动**：反例没有变更细节、证据和风险；正例五段齐全，未验证的事项明确写出。

## 8. [hybrid] README：解释段 Google，步骤段 STE

**反例**：本工具是一个简单易用的命令行工具，可以让你快速搞定部署。首先你需要安装它，然后执行命令即可。
**正例**：

`deploy-tool` 读取 `deploy.yaml`，按其中定义的顺序发布服务。它不修改源仓库。

安装并验证：

1. 运行 `pnpm add -g deploy-tool`。
2. 运行 `deploy-tool --version`。预期输出：`2.4.0` 或更新版本。

**改动**：正例第一段按 `google` 解释工具行为，不夸大；步骤按 `ste`，每步一个动作、命令可复制。

## 9. [hybrid] PRD 需求条目：含糊需求 → EARS 化

**反例**：系统应适当处理异常情况，保证服务稳定，基本不影响用户体验。
**正例**：

- R-14：当数据库连接失败时，订单服务应返回 503，并在 30 秒内重试，重试不超过 3 次。
- R-15：若重试 3 次后仍失败，订单服务应把请求写入死信队列，并向运维通道发送告警。

验收场景（验证 R-14，节选）：

```gherkin
Scenario: 数据库连接失败时重试
  Given 订单服务已启动
  When 数据库连接连续失败
  Then 订单服务返回 503
  And 30 秒内重试不超过 3 次
```

**改动**：反例的「适当」「基本不影响」无法验收；正例拆成两条 EARS 需求，分配稳定 ID，条件在前、动作可测；需求条目遵循形式语法，条目之外的背景解释按 `google` 风格。

## 10. [ste] 中文句法：主语、代词、名词堆叠、长定语

**反例**：提交后自动跑测试，失败就打回。
**正例**：开发者提交代码后，CI 自动运行测试；测试失败时，CI 拒绝合并。
**改动**：主语省略使「人做」与「程序自动做」分不清；每个动词都应能说出施事，主语更换时写出来。

**反例**：`Client` 把请求交给 `Pool`，它负责重试。
**正例**：`Client` 把请求交给 `Pool`。`Pool` 负责重试。
**改动**：「它」可指 `Client` 也可指 `Pool`；代词能指两个对象时，写出实名。

**反例**：缓存服务连接池超时重试策略。
**正例**：缓存服务的连接池超时后，怎样重试。
**改动**：名词连堆看不出谁修饰谁；用「的」或动词拆开，术语表里的词算一个词。

**反例**：按用户 ID 分片的、写入后异步复制的、保留 30 天的订单表。
**正例**：订单表按用户 ID 分片。写入后异步复制，数据保留 30 天。
**改动**：三个「的」叠在名词前，读者要先记住全部修饰才能读到名词；拆成短句，修饰移到名词后或独立成句。

## 11. [ste] 术语一致：一个概念一个词

**反例**：服务启动时加载配置。重启后重新读取设置。修改参数后需要重新初始化。
**正例**：服务启动时读取配置。修改配置后，重新启动服务。
**改动**：「配置」「设置」「参数」是同一个文件，「启动」「初始化」是同一个动作；换词让读者以为是不同事物。正例全文固定用「配置」「启动」，新概念先记入项目术语表再使用。
