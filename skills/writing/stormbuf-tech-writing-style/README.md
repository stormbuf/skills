# stormbuf-tech-writing-style

技术写作风格控制 skill：一个 skill，三种模式——`google`（Google 开发者文档风格）、`ste`（ASD-STE100 简化技术英语原则子集）、`hybrid`（默认，按内容块切换）。

## 为什么存在

1. **AI 写的技术文档冗长、有 AI 腔** —— 解释类文字交给 Google 开发者文档风格：第二人称、主动语态、条件前置、术语一致。
2. **操作步骤含糊、不能照做** —— 动作类文字交给 ASD-STE100 简化技术英语的原则子集：一句一动作、条件在前、明确施事、安全说明三要素。
3. **两类内容混在一起，风格互相污染** —— hybrid 模式按「内容块」切分：解释块自然可读，动作块可执行；外加五项任务汇报协议（状态 / 变更 / 证据 / 风险与假设 / 待决策）。
4. **需求文档含糊到无法验收** —— PRD 走 EARS 需求语法 + Gherkin 验收场景的形式语法，含糊词零容忍。

## 适用场景

- 写作对象：技术文档、README、API 文档、设计说明、PRD 与需求文档、runbook、操作步骤、错误信息、验收清单。
- 对话场景：技术任务（vibe coding、需求分析、排障）中的变更汇报。
- 不适用：营销文案、品牌文案、文学创作。

## 三种模式

| 模式               | 用于                                         | 风格要点                                            |
| ------------------ | -------------------------------------------- | --------------------------------------------------- |
| `google`         | 解释类内容块：概念说明、架构原理、文档正文   | 自然可读：第二人称、主动语态、短句、条件前置        |
| `ste`            | 动作类内容块：步骤、命令、错误处理、验收清单 | 单一含义、可执行：一句一动作、祈使句、条件在前      |
| `hybrid`（默认） | 同一篇文档混用两类内容                       | 按内容块切换：解释块按 `google`，动作块按 `ste` |

模式选择规则、切换规则与「内容块」的完整定义见 [SKILL.md](SKILL.md)。
